# ADR-0001：文档权威层级与旧开发文档归档

- 状态：已采纳（2026-09-16）
- 关联：`ARCHITECTURE.md`、`AGENTS.md`、`docs/INDEX.md`

## 背景

重构前，代码结构与依赖规则由 `docs/development/architecture.md` 等多份文档分别维护，
文档间互相引用、部分内容随实现演进失真；代理与开发者可能按过时描述施工。

## 决策

1. **根目录 `ARCHITECTURE.md` 是目标架构的唯一权威**；重构期内任何开发以它为准。
2. 旧开发文档（含原 `architecture.md`、`logging.md`、`planning/`、功能设计文档与扩展背包七册）
   整体迁入 `archive/docs/development/`，**仅供历史参考与迁移取证，不得作为落地依据**。
3. 执行型文档（基线、台账、验证矩阵、ADR）放在 `docs/refactor/`，只记录状态与证据，不重复架构理由。
4. 「结构」类内容（层分布、依赖、资源、JNI、基线）由脚本生成或校验（`gen_baseline_doc.py`、`check_*.py`）；
   人工只维护「为什么」（决策与理由）。
5. 文档与实现不一致时：**构建/校验失败**，必须显式修改设计（走版本记录）或登记带文档锚点的临时豁免。

## 后果

- 正向：单一事实源；旧文档不会再被当作规范；结构描述随脚本自动保鲜。
- 代价：归档文档中的链接在新位置仍需引用者自行改路径（已同步更新仓库内引用）；
  历史归档 `docs/history/` 内的旧引用保持原样（历史记录不追改）。
