# ADR-0003：重构分支与 worktree 策略

- 状态：已采纳（2026-09-16）
- 关联：`ARCHITECTURE.md` §11 阶段划分

## 背景

重构与主线修复并行存在：主线（`master`）继续产出功能与修复，重构在独立分支推进。
需要明确「何时开分支、何时用 worktree」，避免并行 lane 互相踩踏。

## 决策

1. 重构统一在 **`refactor/arch-v2`** 分支推进；主线改动留在 `master`，重构分支定期合并主线。
2. **P0–P3 不使用 worktree**：协议、骨架、样板、接口稳定阶段高度串行，集中在一个工作区更安全。
3. **worktree 用于并行 lane 与高风险试验**：需要**并行推进**的插件迁移各自开子分支 + worktree（从集成分支切出，合并方向「子分支 → 集成分支」）；**串行 lane 直接在集成分支执行**（单写者隔离），不额外开 worktree。
4. **核心机制与其最小验证载体**（阶段 A 的 patch/调度/能力/分派，见 `ledger.md` §6）在**集成分支串行**完成并冻结接口；插件迁移**若需改核心**（如新增 `game/access` 访问器），核心件先在集成分支**单独提交冻结**，再提交插件迁移（提交粒度上保证核心先于插件）；**仅当需要并行**时才为插件开子分支 + worktree。
5. **公共核心目录（`contracts/`、`infra/`、`hooks/`、`patch/`）禁止多 lane 并行修改**；
   若某插件迁移必须改核心，先在集成分支完成并冻结接口，再开子分支。
6. 高风险试验或一次性探针单独 worktree，用完即弃，不并入集成分支。

> 修订（2026-09-17）：第 3/4 条按实际执行模式收窄——lane 串行时用集成分支（核心件先提交冻结，再提交插件迁移）；worktree 预留给并行 lane 与高风险试验。理由：串行 lane 下 worktree 隔离收益小，且会引入 Gradle 缓存与构建脚本的根路径绑定问题。

## 后果

- 正向：并行度按阶段递增；核心契约不会被多 lane 同时改写；主线不被重构阻塞。
- 约束：同一 Git 分支不能同时检出到多个 worktree，子 lane 必须各自建分支；
  lane 文件所有权需在开工前声明（与本决策第 4 条一致）。
