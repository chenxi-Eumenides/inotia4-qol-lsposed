# core.item 硬约束

> 只记录不能因架构改变而违反的约束。
> 不包含：空间袋号、pending 通道、import/remove 方法、item handle 类型、free/rollback 机制、28 个 hook 的具体选择、插件拆分、ItemData/codec 位置、capability/HTTP ID、兼容性。

## 1. 游戏原生 ABI 与状态

### 1.1 原生调用边界

- 调用任何原生函数时，参数必须落在该函数的合法域内；原生 bag/slot 必须是游戏认识的索引。
- 自定义袋源/扩展空间可以在 hook 内分流处理；**不要把自定义 space_id 传给原生函数再指望内部 hook 补救**。自定义路径应直接返回，不调用 backup。
- 如果调用 backup：ABI、返回类型、返回值和副作用必须保持原版语义；一个原生副作用只能发生一次。
- 所有原生调用、hook 回调、袋源回调只在游戏主线程执行；不得阻塞、异步等待或跨线程持有游戏对象。
- 裸 `void* item` 指针不能跨调用/跨帧保存；需要稳定身份或每次重新定位并复核。

### 1.2 原生袋与任务袋

- 原版空间袋索引有自己的范围；原版任务袋（原版袋索引 5）只读，不能作为动作/转移的源或目标。
- 改版/C18 追加袋的索引只在其空间内有效；原生函数只接受它自己的袋号域，不接受插件自定义空间号。
- 具体 `space_id`/扁平袋号编码是插件约定，不是游戏约束；只有“调用原生时使用合法原生索引”是硬约束。

### 1.3 S2 数量编码

- 数量是 `128a+b` 位域；写侧没有统一 setter，各写点自行完成门控与回写。
- 只对 `applied 999` 且 count-encoded 类别启用 S2 写回。
- 写入前必须采样 pre 字段，写入后确认 post 字段；`post == pre` 不得推断写发生。
- `delta % 128 == 0` 的合并只能靠“源槽已不再指向被移动对象”证明。
- 确认失败必须 fail-closed；不得凭相等/猜测回写。
- 物理槽扫描用于确认对象指针未被释放/替换；不能用逻辑袋路径替代。

### 1.4 原生副作用必须发生

无论架构如何，以下游戏行为不能由插件伪造或跳过：

- 库存查询/计数、消耗、移除、保存、移动。
- 装备、卸下、使用、销毁、出售、镶嵌、拆分、制作。
- 原生 UI 刷新与装备事件处理。
- 原生函数返回失败时，插件不能把失败伪装成成功；需要补偿时由调用方显式处理。

### 1.5 存档调用序列

- `FindSaveSlot` 与 `SaveItemDirect` 是两次独立原生调用；后者没有额外参数携带前者的目标。
- 如果要把保存重定向到自定义目标，必须自己处理这两次调用之间的关联；具体用 pending、扁平袋号、token 还是别的机制，是实现选择。
- 保存/读档必须保持物品身份、数量和 payload 一致；不能产生半对象或读档后数量漂移。

### 1.6 payload

- 如果使用游戏原生序列化 payload：固定 256 字节，有效长度 1..255，不得动态扩容。
- payload 是来源定义的序列化状态；接收端在回调期间复制需要保留的数据。
- 部分堆叠时，本次数量必须与 payload 内数量语义一致（如果该 payload 编码数量）。
- payload 的具体结构、是否把 item_id/count 放在里面，由物品数据层定义；不是所有架构都必须沿用。

## 2. Hook / 宿主框架约束（条件性）

如果继续使用现有 hook/resource 框架：

- 入口 hook 必须通过 `on_resource_ready` 取得 backup；调用 backup 才是原生路径。
- required 资源缺失时 fail-closed（透明透传原版）；optional 诊断可 fail-soft。
- 同一入口只能有一个 owner；不能两个插件同时接管。
- hook 返回必须保持原版 ABI；不能用一个插件错误码替代原生返回值。
- claim 的 step budget、resumable、private 等是宿主框架语义，必须遵守。

注意：**28 个 hook 的具体集合、claim 表、hook 归属是当前实现选择，不是游戏硬约束。** 换架构可以选择不同拦截点，只要原生副作用和返回值语义不变。

## 3. 正确性不变量

这些不是“游戏 API 规定”，而是产品/数据正确性要求：

- 不复制、不丢件；物品数量与位置一致。
- 不部分成功：多步操作失败时，不能留下“物品已扣但目标未加”“钱已加但物品未扣”等状态。
- 过期身份必须拒绝；不能用相同 bag/slot 数字猜测归属。
- 任务袋只读。
- 保存/读档后数量、身份、payload 语义一致。
- 如果保留外部袋源：来源写入失败不得留下部分对象/持久化改动；导出一律只读。

具体用 free、回滚、预检、事务日志还是别的机制，不受约束。

## 4. 一句话总结

硬约束只有：**原生 ABI/索引域、主线程、裸指针生命周期、S2 位域、任务袋、存档两段式调用、原生副作用、payload 边界、以及“不复制/不丢件/不部分成功”的正确性不变量。** 其余都是实现选择。
