# 插件架构设计指导（基于 extension_bag 重构实践）

本文把 `extension_bag` 的分层重构沉淀为可复用的设计准则，供其他插件重构时对照。
目标不是让所有插件长成一样，而是给出**依赖方向、线程契约、数据边界和迁移顺序**的
统一判断标准。

## 1. 分层模型

已在 extension_bag 落地的七层结构（L0 最低，L6 最高）：

| 层 | 职责 | 典型内容 |
|---|---|---|
| L0 | 纯模型与契约 | 数据结构、规则函数、`contracts/` 宿主 ABI |
| L1 | 基础运行时 | 状态、快照、日志、锁/重入、只读访问器 |
| L2 | 持久化 | sidecar/slot data 读写、版本迁移 |
| L3 | 事务 | 多步操作、pending、回滚、失败隔离 |
| L4 | 用例 | 校验 → 事务 → 刷新，返回类型化结果 |
| L5 | 核心适配 | 生命周期、事件路由、控件状态、原生交互 |
| L6 | 接口 | HTTP/API/JNI/UI 面板/装配 |

**唯一依赖规则：只允许高层 include 低层。**

判断方法：从 L4 往上找 `#include`，如果出现 UI 控件、坐标、JSON、`_bridge` 或
反向依赖，说明边界破了。

## 2. 状态与数据边界

### 2.1 状态分层

- **业务状态**（袋、物品、模式、选中）：只由 L1 状态模块持有。
- **控件/页面状态**（句柄、rect、页签、投影窗口）：只由 L5 `core/ui_state` 持有。
- **持久化状态**：只由 L2 读写，L1 不直接碰 slot data。
- **查询快照**：L1 发布不可变快照，L6 只读快照；写路径才改 live state。

判断标准：如果一个结构里同时出现业务字段和控件指针，它应该被拆开。

### 2.2 数据驱动边界

- **游戏数据**（物品属性、袋容量、原生袋布局）：只读宿主数据，不复制。
- **构建期数据**（变体表、能力位）：由脚本从 APK 生成 `.inc`。
- **运行期配置**（数量、开关）：sidecar 或设置项，带 schema 版本。
- **业务规则**（事务允许矩阵）：留在代码，不强行 JSON 化。

经验：**环境适配数据化，业务规则代码化**。把规则搬进 JSON 会引入解析、校验、
迁移和调试成本，收益通常不抵。

### 2.3 编号域

- 不同来源的 ID 必须显式分域（原生袋、扩展袋、控件 child index、事务 ID）。
- 不要复用某个域的“空值/哨兵”到另一个域。
- 编号字段宽度按未来上限选（例如袋号用 `int32_t`，不要用 `uint8_t` 省空间）。
- 跨域只允许“映射”，不允许“借用”。

## 3. 线程与重入

### 3.1 主线程模型（推荐）

- 业务状态只在游戏主线程读写。
- 外部写命令：`post_typed` 入队 → 主线程 drain → 票据回取结果。
- 外部查询：读不可变快照，不触碰 live state。
- 原生回调：主线程同步执行，不做跨线程等待。

### 3.2 重入

- 用**线程局部入口守卫**（`EntryGuard`）判断“是否已在本次调用栈内”，
  不要用 `try_lock` 当重入检测。
- 需要允许嵌套的地方用深度计数锁（`ReentryLock`）；需要拒绝的地方用
  `TryReentryLock`。
- 重入策略要显式：读返回快照/回退，写拒绝并记日志。

### 3.3 禁止

- 在持有业务状态时调用可能回调自身的外部接口（会自死锁或半状态）。
- 在绘制/查询路径写业务状态。
- 用 `recursive_mutex` 掩盖设计问题。

## 4. 原生访问准则

1. **地址只在 game/access 层**：插件业务代码不出现裸偏移。
2. **能力位优先于版本号**：用 `has_capability` 判断改版差异。
3. **句柄 + generation**：跨帧只传 handle，不传裸指针；使用前复核 generation。
4. **失败即拒绝**：探测失败、布局歧义、句柄失效时 fail-closed，不猜。
5. **探测与 UI 解耦**：能从数据表读到的（袋数量、容量）不要依赖面板控件树。
6. **临时值必须恢复**：借用全局状态（如 `current_bag`）做显示时，绘制后恢复 raw。

## 5. 接口层准则

- L6 只做：参数校验、JSON 组装、票据、控件事件翻译。
- L4 返回**类型化结果**（`ok/错误码/数据`），不返回 JSON 字符串。
- 查询与命令分开：`bag_query` 读快照，`bag_command` 走用例。
- 所有入口带线程契约与重入守卫；错误语义明确（错误码 + 上下文）。

## 6. 迁移 playbook

按以下顺序做，每步一个可回滚提交：

1. **基线**：统计 L4 直接状态引用、锁获取、反向 include、宏桥数量。
2. **查询快照化**：先把只读接口改成读不可变快照，去掉读路径的 live 访问。
3. **命令编组**：写操作统一入队主线程，票据返回；保留旧同步入口做薄委托。
4. **用例层**：把命令实现搬进 `usecases/`，返回类型化结果；L6 只做组装。
5. **组件抽取**：状态、事务、投影、布局、所有权、拖拽各自成文件与窄头。
6. **删锁**：确认所有入口主线程后，把互斥量换成重入守卫；逐个替换
   `try_lock` 语义。
7. **头文件收口**：删除聚合头与 `_internal` 宏桥，按层拆窄头，加 CI 反向依赖检查。
8. **数据驱动**：把上限、容量表、变体表改成生成表 + 运行期配置。

每步都要满足：Host 测试全绿 + Android Debug 构建 + 受影响路径真机 smoke。
Host 测试不编译全部 TU，**只跑 Host 会漏编译错误**。

## 7. 反模式清单

| 反模式 | 症状 | 处理 |
|---|---|---|
| 聚合头 | 一个头 include 所有实现 | 按层拆窄头，删聚合头 |
| 宏桥 | `#define foo foo_internal` + 转发包装 | 直接定义公共名，删宏 |
| JSON 进用例 | 业务层拼字符串 | 返回类型化结果，L6 组装 |
| 控件进核心 | L1–L4 出现 rect/handle | 移到 L5 `ui_state` |
| 双写路径 | HTTP 与 UI 各写一套状态 | 统一走用例/事务 |
| 哨兵复用 | 用 6 表示“无选中” | 动态计算或显式可选类型 |
| 裸指针缓存 | 跨帧保存控件/物品指针 | handle + generation |
| try_lock 当重入检测 | 忙时静默丢事件 | 线程局部入口深度 |
| 版本号分支 | `if (version == v514)` | 能力位/运行时探测 |
| 全量快照 | 每次写复制全部数据 | 元数据快照 + 分页查询 |

## 8. 测试与验收

| 层级 | 测试 |
|---|---|
| L0 | 纯规则单测（无宿主） |
| L1 | 快照一致性、重入、状态机 |
| L2 | sidecar 往返、版本迁移、越界拒绝 |
| L3 | 方向矩阵 + 失败注入 + 回滚 |
| L4 | 用例参数校验、结果类型 |
| L6 | HTTP 参数/票据、UI 事件翻译 |
| 静态 | 反向 include、裸地址、JNI 导出、宏桥 |
| 真机 | 开包、切页、跨袋移动、重启恢复 |

源码断言测试（检查关键调用顺序/锁语义）很有用，但重构改变机制时要同步更新，
否则会变成“测试保护旧实现”。

## 9. 完成定义（DoD）

1. 依赖只向下；反向 include 为 0。
2. L1–L4 不含控件、坐标、JSON、`_bridge`。
3. 聚合头与宏桥为 0。
4. 业务状态只在主线程；写命令编组；查询读快照。
5. 无业务互斥量；重入策略显式。
6. 编号域分离；无跨域哨兵；字段宽度满足目标上限。
7. 数据驱动边界清晰：环境数据化、规则代码化。
8. Host 全绿 + Android 构建 + 受影响真机验收。

## 10. extension_bag 参考数字

- 分层：L0–L6，反向 include 0。
- L4 直接 `runtime_state()`：935 → 0。
- 业务互斥量：116 个获取点 → 0（改为重入锁）。
- 聚合头：删除；宏桥：0。
- 用例：view/item/unequip/move/set_bag_count，返回类型化结果。
- 数据驱动：变体表、袋 catalog、`bagCount`（1..128）。
- 验证：CTest 160/160、`check_arch` 全绿、Android Debug 构建。
