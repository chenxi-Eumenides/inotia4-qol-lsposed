# Infrastructure inspection: near-call thunk mmap

**Date:** 2026-10-13  
**Scope:** review the current `call_patch` near-address mmap fallback and available Host test evidence. This note does not change or replace prior audit evidence.

## Source-confirmed behavior

- `module/app/src/main/cpp/patch/call_patch.cpp:251-307` first requests `MAP_FIXED_NOREPLACE`. If mmap returns a different address, the code unmaps it, switches to ordinary hint mode, and retries. `EINVAL` also triggers the hint fallback. Both modes check the actual mapping for page alignment and BL branch reachability before accepting it; invalid mappings are unmapped.
- `module/app/src/main/cpp/patch/call_patch.cpp:375-385` logs requested and actual addresses, fallback mode, failure stage, errno, and `uname` kernel release. No runtime failure log was available in the local evidence set for this inspection.
- `module/app/src/main/cpp/tests/test_host.cpp:233-310,379-394` uses injected mmap/munmap functions to cover an unexpected `MAP_FIXED_NOREPLACE` return address, `EINVAL` fallback, `EEXIST` candidate advance, and an out-of-range hint mapping. These are deterministic Host seam tests; they do not execute against an Android kernel.

## Frame, event, and cache inspection

- `module/app/src/main/cpp/host/frame_source.cpp` dispatches scheduler and legacy frame tasks from the render-pre and logic-pre game hooks, then invokes the displaced game call. Cache builders are injected at assembly, but its frame task is scheduled lazily after a slot is first requested and dispatched from logic-pre; `game_cache.cpp` checks the injected game-main-thread gate before running a builder. `test_game_cache.cpp` supplies fake frame/world/main-thread gates and JSON builders, and includes the production scheduler to assert its real logic/render dispatch phase; it does not link Android or a live Game Host.
- `game_cache_tests` now verifies write-triggered reads only build inline during an actual main-thread `LogicPre` callback, and return `not ready` rather than an older published JSON when read outside that safe phase or when the current build fails. A successful refresh returns the new slot version; six concurrent readers share one newly published slot result. A reader without a publishing frame uses one bounded condition-variable wait and fails closed; this is not a repeating frame-clock polling loop.
- `host/module_health.cpp` owns the health snapshot and dispatches revisioned observer callbacks when facts change; new subscribers receive the current snapshot. `PluginRuntimeEffects` consumes pushed Host effects, and the internal config receipt observer is one-shot, has a 256-observer bound, replays an already-terminal receipt outside the controller mutex, and sends canonical receipt JSON through JNI. These paths do not use a 1-second native poll or 200ms/50ms receipt timer. `MainActivityStartupHook` coalesces actual `onCreate`/focus events onto its startup worker and has no timer retry; a rejected observer token remains retryable on a later real Activity event. The source-level `RuntimeObserverRetryStateTest.kt` covers rejected API/health subscriptions, late snapshot replay, and coalesced retries. The public HTTP receipt and `/api/system/events` contracts remain available to callers that choose polling; `ApiServer`'s 500ms listener reconciliation is a cancellable one-shot debounce.
