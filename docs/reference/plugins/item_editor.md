# item_editor

`item_editor` 是仅显示的物品详情面板，入口位于背包页右上角自动出售按钮左侧。插件 feature `item_editor.panel` 默认关闭，且必须开启 OP 才能使用。

编辑阶段使用 `ItemEditorDraft` 内存镜像：进入面板时把当前物品快照复制到 draft，后续 UI 只读写 draft，不写实际物品。点击“类别”打开类别卡片：36 个 `ITEMCLASSBASE` 类按武器/装备/物品三组、每行三列展示，可滚动；单选，再次点击取消，确认只改 draft，取消不改。同类确认等价于取消；跨类必定丢弃具体 `item_id`，装备族之间保留前缀、词条、孔、强化、混沌和法伤率，装备族与物品族之间只保留数量，宝石属性只在宝石类内保留。可堆叠的非装备类别可打开独立模态卡片临时调整数量：默认范围 1..99；`stack_limit.limit_999` 可用且启用时上限为 999，功能不可用或未启用时上限为 99。确认写入 draft，取消丢弃临时值。draft 的实际提交经由主面板右侧动作列完成（见下文动作按钮段落）。

面板使用一个带装饰角的 60% 黑总底框；关闭按钮位于屏幕左上角。左侧保留一层自定义框，物品图标在 74×74 格内按 64×64 范围居中，名称固定在图标下方；类别行固定在名称行下方、不参与滚动。未选择类别时，物品格灰显、名称行灰显，两者的点击回调都被拦截。非装备物品显示数量；可堆叠物品的数量行可打开 420×250 模态卡片，四列两行的增减按钮按 1、10、100、1000 调整并实时显示当前值，范围为 1..99；仅当 `stack_limit.limit_999` 可用且启用时上限为 999。不可堆叠物品的数量固定为 1，数量行灰显且不可点击。装备显示前缀、强化耐久度、总宝石孔数、非零伤害/防御/魔法攻击、需要等级及混沌属性倍率；混沌等级固定为 0，不提供编辑入口。混沌属性倍率参与 `ITEM_GetDamage`/`ITEM_GetDefense`（伤害/防御/需要等级）。C18L 还把 `ITEM_GetOptionValue` 改成按倍率缩放，因此详情页词条与普通属性词条（kind 1）都按倍率显示/生效，但主属性词条（option 行 0..4：力量/敏捷/体力/智力/精力）由 `CHAR_CalculateStatusFromEquipDetail` 直读节点、不乘倍率；卡片在该变体下注明「主属性词条（力/敏/体/智/精）不受倍率影响」。其他变体的词条整体不参与倍率，卡片注明「仅影响伤害/防御，词条数值不变」。选择物品或确认前缀时通过 `QOL_PORT_ITEM` 5.7 的 `read_item_stats_full` 按当前 raw rarity、强化 ID/次数和混沌状态读取并回填伤害、防御、魔法攻击倍率、需要等级和可堆叠标志；伤害/防御按原版 `ITEM_GetDamage`/`ITEM_GetDefense` 的表与公式重算（品级、强化、混沌），需要等级按 `ITEMDATABASE +3` 能力等级 + 混沌等级夹 0..105，魔法攻击倍率直接取 `ITEMCLASSBASE +0xB`，全程不创建临时物品；失败时保留 draft 当前值并记录结构化日志。各属性在可滚动的原生选项行中展示，key 左对齐、value 右对齐，按下显示金框。物品卡为四列布局（174×112 单元格、176 步长、760 宽卡片），候选按所需等级升序、同等级按 item_id 升序；装备候选名称附带所需等级，名称最多显示 8 个 UTF-8 codepoint，等级后缀保留。只绘制完整落在列表可视区内的槽位，避免越过确认/取消 footer。类别使用 `QolItemType` 中文名称及枚举 ID；装备类别直接显示子类名（如“双手武器”），不再显示“装备（双手武器）”。前缀行点击打开 760×400 选择卡片，不显示标题；raw 0..14 全部可选，按白/绿/蓝/黄/紫品质分组为五列，列宽 138、列间距 146；当前变种/类别没有对应名称的 raw 显示“无前缀”。C18 名称只出现在 C18 变种，其他变种不显示 C18 专属名称。确认只更新 draft，取消不改。物品格的品质角标由 raw 前缀映射，绘制游戏原生 unit 0x10 loc 5–8（绿/蓝/黄/紫；白色无原生角标）；物品卡中的候选物品不显示角标。魔法攻击数值按伤害乘魔法伤害倍率除以 100.0 计算并显示一位小数。物品图标使用 `core.custom_ui` 的 `item_slot` 组件，组件只接收物品 ID；格底来自游戏原生 `UI_003`（unit 15 loc 41，74×74），不采用自绘框。右侧始终显示三个标题，每段词条框数量对应只读数据中的实际数量，标题行不画背景；仅装备可用全部三段，宝石仅可用宝石词条段，其他类型的词条框灰显。宝石本体自身的宝石词条由 `jewel_attribute_type`/`jewel_value` 生成，不依赖空的 `jewel_options` 列表。装备词条数值的颜色通过 `attribute.quality` 查询并由 UI 适配器解析，与属性范围显示使用相同颜色；宝石、附魔词条和非装备不染色。词条数值按静态数据标记显示整数或一位小数百分比；未知名称显示“未知”，不推测名称。每个实际词条行右侧的 `×` 与标题行 `+` 同列对齐。装备详情通过 `UIDesc_GetData` 取当前物品对象，避免误用背包光标首格；静态数据与快照只读，不会修改实际物品。

右侧每条可用词条均可通过“编辑”打开 760×500 统一编辑卡。左侧按 ID 分为基本（0..4）、进阶（5..16）、特殊（17..88）三列，每列独立滚动，空名称显示 `ID n`；右侧显示名称、ID、当前值与 ±1/10/100/1000 调整，底部确认/取消。普通选项 ID 范围为 0..88、数值范围为 -32768..32767，宝石本体 ID 范围为 0..63、数值范围为 0..2047；百分比数值以 `value/10.0` 加 `%` 显示，宝石本体始终显示整数。确认只写入 draft 并标记 dirty，取消不修改；词条编辑卡与删除确认卡互斥。真机界面与图标绘制尚未验收，见 `VM-ITEM-EDITOR-01`。

装备“强化强度”只列低级/中级/高级/顶级/特级五种：`ITEMENCHANTBASE` 的混沌武器/防具行（类别 20/25，第 15/31 行）类别位掩码为 0，任何类别都选不到；游戏 `ITEMSYSTEM_EnchantItem` 对这两个类别走独立分支，要求物品已强化、附加强化次数为 0，不消耗耐久，只把已强化次数 +1（成功判定再 +1），不写附魔 ID。附魔行映射为：武器 `行 = 档位×3 + 组`、防具 `行 = 16 + 档位×3 + (组−3)`，`ID = 行 + 1`（C18 为 4 位 ID，行 0..14 → 1..15；其余变体 5 位，行 0..30 → 1..31）。`build_payload` 在装备场景拒绝超出 ID 宽度的值并记 `fail_step=enchant_id`，不再静默截断成别的行号。

主面板 rect 右侧 20px 处使用独立 `panel_create` root 承载动作列（不被主面板裁剪）：三个 72×72 圆角方按钮纵向步距 84，起始 y 为面板 y+150，依次为放入背包、生成掉落、替换物品；替换物品仅当 `source_valid` 时创建，否则整个按钮不显示。每个按钮的四个汉字按 2×2 画在四个象限（font 0；可用时金色，draft 无具体 item_id 或 class 无效时灰色），底图经 `draw_help_option_row` 按 `control_pressed` 按下态绘制。点击打开 `ui_confirmation` 1.1 `open_text` 原生 Yes/No 文本确认框（消息分别为“放入背包？”“生成掉落？”“替换物品？”）；确认回调只记录 pending action，由 `panel_process` 在主线程安全点执行，取消清空；确认框打开期间按钮不重复触发，token 保存、面板销毁时 close 未完成的确认框。动作列事件经 `dispatch_native_event` 派发给独立 root，模态卡存活时仍优先吞掉事件。payload 由 `item.payload` 1.1 `build` 按 draft 生成（header.uid=0）：`type_flags=(item_id&0x3ff)<<6|(raw_rarity&0xf)<<2`；`count_field` 宝石本体为 `((jewel_attribute_type&0x3f)<<18)|(jewel_value&0x7ff)`、装备为 `100<<25`（仅 `chaos_flags&3` 命中时再或 `chaos_level&0x7f|((chaos_rate&0xff)<<8)`）、其余为 `(count&0xff)<<25`；`magic_rate` 取 draft 值，`socket=((socket_total&0xf)<<4)|(socket_filled&0xf)`，`enchant=((enchant_id&0x1f)<<11)|((enchant_level&0x1f)<<6)|((enchant_remaining&0xf)<<2)|(chaos_flags&3)`；词条按 native→jewel→enchant 合并、跳过 id<0 空词条，`code=(type<<13)|(id&0x1fff)`、value 为 s16。放入背包：`inventory.action` 3.4 `create`（flags=`kQolItemCreateFlagAllocateUid`、category=item_id、count=1）得到 detached 句柄后按 `QolItemPlaceTarget{ref={0,-1},slot=-1,flags=kQolItemPlaceFlagMerge}` 落位，落位失败不再 discard（原生写槽失败时对象可能已由 Host 释放）；落位成功后经 `inventory_refresh` 1.2 `call_original` 刷新原版物品区（就是 `UIEquip_RefreshItemArea` 的 backup trampoline，core.item 原版售出结算同路），能力不可用时按 no-op 降级并记 `step=refresh result=skipped`，因此放入后不再需要切袋/切页才可见。生成掉落：create 出 detached 句柄后调 `QOL_PORT_ITEM` 5.6 `read.drop_item`，成功后句柄失效不再 discard，失败先 `discard_handle` 再报错。替换物品：要求 `source_valid`，构造 `QolBagTransfer{category=item_id,count=1,payload}` 调 `inventory.transfer` 1.1 `replace_item`；payload 原地覆盖目标对象（保留对象地址与装备槽指针），写入成功后若目标正被队员（0..2）或当前菜单角色装备，则重设同一装备槽（`CHAR_SetEquipItem` → `CHAR_InitializeFromEquip`），刷新角色属性缓存与装备显示。动作成功或失败面板均保留、不关闭也不重建 draft，按钮列下方显示成功/失败短句（另在未选择物品时显示灰提示）；失败记录 `op=action ... result=failed ...` 结构化日志。能力（`item.payload`/`inventory.action`/`inventory.transfer`/`ui_confirmation`）每次调用现取，不可用时按钮报状态并写日志。
