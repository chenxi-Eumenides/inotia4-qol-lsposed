# `item_lab` 物品构造测试

`item_lab.construct` 启用后，在背包页自动出售按钮左侧显示「造」按钮。点击一次会固定构造 5 件测试物品；若当前原生背包 slot 0 有物品，先额外复制一件到当前袋空槽并申请新 UID。

| 类型 | category | 数量 / 属性 |
|---|---:|---|
| 恢复药水（小） | 5 | count=7 |
| 高级宝石 | 30 | count=1，属性类型 0（力量），值 60 |
| 合法白色装备 | 462（基础短剑） | rarity=0（白），原生词条 0，孔 2/已镶 0，宝石节点 0，附魔 0 |
| 合法蓝色装备 | 473（基础布甲） | rarity=2（蓝），原生词条 2，孔 2/已镶 2，宝石节点 2，附魔 1 |
| 非法装备 | 462（基础短剑） | rarity=4（紫）但原生词条仅 1（应 4）；孔 2/已镶 1 却带 1 个附魔（应 0） |
| slot 0 副本（如有） | 源物品类别 | 源数量；UID 由游戏重新分配 |

## 装备合法性口径

- `ITEM_IsRealEquip` 读取 `I_COUNT` bits25-31 的装备 marker；值必须 `> 99`。构造 payload 固定写 `100 << 25`，否则装备会显示为未鉴定/损坏。
- 原生词条（type=0）数量必须等于品质档位：白 0、绿 1、蓝 2、黄 3、紫 4。
- 宝石节点（type=1）数量 = `socket_filled`，且 `socket_filled <= socket_total`。
- 只有 `socket_filled == socket_total` 时才允许 1~2 个附魔节点（type=2）；未满孔时附魔必须为 0。
- 固定 rarity 到 `I_TYPE` bits2-5 的映射：白 0、绿 4、蓝 7、黄 10、紫 11。

## 预期与限制

装备 payload 解析预期：category bits 与表一致、rarity raw 与映射一致、`count_field=0xC8000000`、三个列表的节点类型数量符合上表。所有新物品由游戏分配 UID；日志域 `item_lab` 逐件记录预期值及实际 `space/bag`。

插件在操作前检查当前袋剩余容量：slot 0 有物品需至少 6 个空位（5 件构造 + 1 件副本），否则至少 5 个。容量不足会 WARN 并跳过整批。当前袋 raw 值 0..4 映射原版袋，6..10 映射改版袋；5 或非法值回退原版袋 0 并 WARN。单件创建或落位失败会记录 WARN，不承诺跨物品回滚。

本插件仅供测试解析、生成、构造链路，避免在重要存档中使用。
