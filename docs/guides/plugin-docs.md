# 插件权威文档写作规范

> 面向编写其他插件文档的代理。范本：`docs/reference/plugins/core.item.md`（对外契约）与 `docs/reference/plugins/core.item-internals.md`（内部实现）。

## 1. 产出物

每个插件只写两份文档：

| 文档 | 路径 | 读者 |
|---|---|---|
| 对外契约 | `docs/reference/plugins/<plugin>.md` | 其他插件作者、HTTP 客户端、集成方 |
| 内部实现 | `docs/reference/plugins/<plugin>-internals.md` | 插件维护者、审计与排查人员 |

约束：

1. 不写第三份插件文档；不把最终结论写进 `docs/refactor/`（该目录会被迁移或删除）。
2. 两份文档只互相链接；需要外部事实时链接 `reference/api-reference.md`、`refactor/verification.md` 这类稳定文档。
3. 两份文档职责不重叠：同一张表、同一段事实只出现在一侧。
4. 在 `docs/INDEX.md` 同时登记两份，标明“对外契约”和“内部实现参考”。

## 2. 分工判定

| 问题 | 归属 |
|---|---|
| 其他插件或 HTTP 客户端能否依赖这个行为？ | 对外契约 |
| 这是调用方必须传的参数、返回结构、状态码或线程约束吗？ | 对外契约 |
| 这是端口常量、hook 资源、内存地址、缓存/队列实现吗？ | 内部实现 |
| 这是二进制格式、恢复流程、失败补偿细节吗？ | 内部实现 |
| 这是当前限制、未验证项、技术债吗？ | 内部实现（对外只写会影响调用的部分） |

对外文档禁止出现内部符号：port 枚举/版本、hook 资源 id、内存地址、journal 二进制布局、缓存字段。

## 3. 对外契约必备章节

| 章节 | 内容 |
|---|---|
| 定位与职责边界 | 一段定位；“拥有 / 不拥有”两列表 |
| 术语与身份 | 编号空间、句柄、引用类型、稳定键与不稳定键 |
| 能力与开关 | capability 表（id、版本、用途）；用户可见 toggle 只写行为 |
| 公共契约 | 外部注册/调用的结构体、回调、语义、版本、线程与失败约定 |
| 操作与行为矩阵 | 调用方可见的分支、合并/覆盖规则、优先级 |
| HTTP surface | 方法、路径、用途、门控；分页与参数语义；错误码含义 |
| 状态与错误 | 枚举与调用方应如何处理；不要复制内部错误映射表 |
| 线程与不变量 | 调用线程、顺序要求、可依赖的保证 |
| 实现指针 | 一句话指向内部文档，不重复内容 |

## 4. 内部实现必备章节

| 章节 | 内容 |
|---|---|
| 分层与目录 | 目录 → 职责 → 代码位置 |
| 装配 | descriptor、ports、resources、features、生命周期入口 |
| 关键机制 | 探测/缓存/队列/批处理/锁；写清缓存键与失效入口 |
| 数据流 | 读、写、后台任务各一条链路 |
| 失败与恢复 | 事务顺序、补偿、journal/重试、降级 |
| 已知限制与风险 | 必须如实：未接线、无调用点、设计目标未实现 |
| 测试与验证映射 | 测试文件、静态检查、真机证据边界 |
| 已删除旧结构 | 旧接口/适配器/兼容层，避免读者按旧模型理解 |

## 5. 写作规则

1. 中文、事实优先、表格优先；不写营销语气和“我们认为”。
2. 每个常量、数量、路由、资源数都从代码核对，并在文中给出源文件路径。
3. 区分“设计目标”与“当前实现”；未验证的写“未验证”，不要写成保证。
4. 不复制：内部文档引用外部文档的章节名，反之只留一句指针。
5. 术语按层使用：空间（如“改版袋空间”）与实现（如“C18 布局”）分开；不要把某个实现的名称当成空间名。
6. 版本号以契约头文件为准；路由数与 `routes.inc`/`routes.cpp` 一致；资源数与 claim 表一致。
7. 限制、债务、无调用点的入口必须写入内部文档，避免后续代理误判。

## 6. 代理执行清单

1. 读 `plugin.cpp`、`contracts/`、`hooks/`、`http/routes*`、`tests/`，列出能力/端口/资源/路由。
2. `grep` 校验数量与版本，记录来源路径。
3. 先写对外契约，再写内部实现。
4. 去重：标题交集必须为空；公共枚举/路由表只在对外；资源/hook/地址只在内部。
5. 检查：对外文档无内部符号；内部文档不复制公共表；两份只互相链接。
6. 更新 `docs/INDEX.md`；`git diff --check`。
7. 不新增 `docs/refactor/<plugin>/` 文档。

## 7. 反例

- 把 hook 清单、port 版本写进对外文档。
- 把 `InventoryActionStatus` 整表复制进内部文档。
- 用“应该”“预计”描述未接线的行为。
- 引用即将删除的 `refactor/` 设计文档作为契约依据。
- 一份文档包办契约与实现，导致调用方和维护者都读不到重点。

