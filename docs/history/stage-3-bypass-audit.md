## 1. 阶段目标与边界

本阶段检查现有上层旁路能否由原版入口替代，并对保留、迁移、退役候选作出静态裁决。它不等于真机覆盖，也不等于删除旁路。

- 不进行真机验证，不批准 P7 Overall。
- 不新增宽泛 `SaveItem` Hook，不接管 P6 保存入口。
- 不把现有 8 个 Native Hook解释为生产者全局覆盖。
- 合成部分提交回滚、生产者运行时行为和保存一致性转阶段 5/P6。
- 扩展对象始终禁止进入 `INVEN_RemoveItemDirect`、`ITEMPOOL_Free` 和原版物理保存路径。

## 2. 旁路裁决

| 分类 | 当前入口/旁路 | 静态裁决 | 后续门禁 |
|---|---|---|---|
| 保留 | 扩展三方向事务、扩展 API 分发、UI 投影/拖动、任务袋门禁 | 原版物理槽无法表达逻辑袋、payload 和五态事务 | 阶段 5/P6证据完成前不删除 |
| 保留 | P6 `module_save` 和 sidecar 协调 | 保存提交时序属于 P6，不由 P7 Hook替代 | 保存异常一致性继续归 P6 |
| 保留 | `ConsumeItem`、`RemoveItem`、装备/宝石适配 | 扩展对象需要逻辑消费、删除和受控装备 | 阶段 4函数级实现，阶段 5真机验证 |
| 迁移 | `FindItem`、`HaveItem`、`GetItemCount`、`IsHavingEmptySlot` | 原版优先，扩展 fallback/聚合；不伪造物理槽 | 阶段 4逐函数 PoC |
| 迁移 | `data_op_use_item`、`data_op_equip`、`data_op_jewel`、`data_op_enchant`中的重复原版模拟 | 效果/规则优先调用原版；扩展层承接物化、逻辑状态、payload、所有权和 UI | 阶段 5回归后，阶段 6逐项删除重复模拟 |
| 暂缓 | 拾取、任务奖励、开箱、拆包、合成、商店、脱装备、快捷键、保存子调用 | 逐 caller核对 context、线程、所有权、失败释放和任务袋门禁 | 阶段 5/P6 |
| 退役候选 | 重复原版效果/扣数量模拟、旧持久化兼容分支 | 只有全 caller、成功/失败、对象、保存和真机证据齐全才删除 | 阶段 6 |

## 3. 已完成的确定性修复

1. 投影扩展宝石不再调用 `INVEN_RemoveItemDirect`，改走扩展逻辑删除。
2. 投影扩展装备不再直接调用原版装备函数，改走受控扩展装备适配。
3. pending 扩展到原版恢复使用 tracked load，并补齐成功 handover、失败 release、源槽清空和目标 payload复核。
4. API 创建物品在不可堆叠、满包或保存失败路径补齐对象释放。
5. 商店购买改为先保存/扣款顺序可检查，保存失败执行退款并显式报告退款失败。
6. 合成材料删除前后增加源对象/物理槽校验，产物保存失败补对象池释放；无法静态证明完整逆操作的部分不添加猜测性回滚。
7. `native_init` 增加显式 default visibility/used，保留 LSPosed Native Hook入口。

## 4. 生产者静态结论

| 生产者 | 当前裁决 | 未闭合项 |
|---|---|---|
| 拾取 | 原版优先，caller级扩展兜底 | 掉落对象释放、线程、满包行为 |
| 任务奖励 | 任务物品保持原版袋 `5`；普通奖励才允许扩展兜底 | 全分支、类别映射、失败回滚 |
| 开箱/拆包 | 不做全局 Hook，保留上层分发 | 多产物部分失败、输入消费时机 |
| 合成 | 保留旁路，逐 caller审计 | 部分提交回滚、5个 caller分支差异 |
| 商店 | 原版物理袋 `0..4`优先；NetworkStore排除 | 商品借用、扣款/入库原子性、堆叠释放 |
| 脱装备 | 原版优先；扩展装备受控物化入库 | 满包、全部 caller、pending恢复 |
| 使用结果 | 原版效果优先；扩展对象不得进入对象池释放 | 创建→保存→消费所有权链、间接 caller |

这些结论只证明静态裁决，不证明阶段 5生产者运行时覆盖。
